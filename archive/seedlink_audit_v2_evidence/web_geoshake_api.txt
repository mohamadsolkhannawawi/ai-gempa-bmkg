Community felt reports · GeoJSON · no key What people felt, one event at a time. After an earthquake, GeoShake app users can report how strongly they felt it. Those reports are aggregated into ~300 m cells and published per event as a plain GeoJSON FeatureCollection on the Modified Mercalli (MMI) scale — QGIS, Leaflet, GDAL/ogr2ogr and geopandas read it as-is. Two endpoints, in this order: /api/intensity lists the events that have data, then /api/intensity/ {eventKey} returns the cells for one of them. This is a human-reported layer: what people say they felt, not what an instrument measured. Keep it apart from the PGA and intensityClass fields of the endpoints above, and from the phone-accelerometer layer on the map — those are machine measurements. No API key is needed here , so the access tiers and the key panel above don't apply to this endpoint. 1 Start here: which earthquakes have data One keyless GET lists every earthquake that has published felt-report data, newest first. Each entry hands you the eventKey for step 2 together with a catalog summary and the counts — you don't build keys, and you don't probe events to find out which ones are worth asking about. cURL Python Entry shape Copy curl "https://api.geoshake.org/api/intensity" # Optional paging — newest first, 1-200 per page curl "https://api.geoshake.org/api/intensity?limit=100&offset=0" limit — 1–200 · default 50 offset — 0–100000 · default 0 total / hasMore — events with data · paging flag cellCount / reportCount — published cells · reporters in them windowEnd — past it, that event's tally is frozen Only events that cleared the publication threshold are listed, which is why the list is empty today — an honest answer, not an outage. Both intensity endpoints are anonymous and rate-limited per IP: over the limit you get 429 , never a fake empty collection. Any key of the same quake returns the same map. Ask for the EMSC record of an event that USGS also published and you get one merged collection — so metadata.event.source can name an agency you did not ask for. That is the merge working, not a mismatch: eventKey always echoes what you asked for, canonicalKey names the group's chosen record, and mergedKeys lists the rest. Reports are counted once per person, so a merged event never double-counts. Building a key yourself (optional). Keys are eq_<source>_<sourceEventId> — USGS event us6000tjl2 becomes eq_USGS_us6000tjl2 , sources being the agencies GeoShake mirrors ( USGS , EMSC , AFAD ). A single catalog record at /api/quakes/ {id} carries both source and source_event_id ; the list endpoint /api/quakes does not, which is exactly why step 1 exists. Records without an agency id use the fallback form eqid_<id> , built from that record's numeric catalog id . One earthquake exists as separate records at USGS, EMSC and AFAD. Reports are stored under the key of the record the GeoShake app notified people about, so another agency's key for the same quake can legitimately come back empty — we don't silently merge the copies for you, and the same physical earthquake can appear twice in step 1 under two agency keys. 3 Know what you are plotting Reports are counted inside the window the response states — windowStart → windowEnd , closing 60 minutes after origin time. Once that window is closed the result stops changing. Read this before you publish a map from it. Values are Modified Mercalli (MMI) intensities reported by people , not measured by an instrument — not comparable with PGA, with intensityClass , or with the phone-accelerometer layer. A cell is published only after at least 3 independent reports ; a single report is never released. That is also why a feature is a ~300 m polygon and not a point : lat / lon is the cell centre, deliberately not a reporter's position, and reportCount sums published cells only. An empty features array is the normal outcome for most events — a 200 with nothing to draw, not a failure. And none of this is an official damage assessment: for that, follow your national seismological and civil-protection authority. Beyond the confirmed catalog, GeoShake streams live waveform data over the seismology community's standard SeedLink protocol. Point ObsPy, jAmaSeis, SWARM — or any SeedLink client — at seedlink.geoshake.org:18000 and watch stations in real time. 1 Connect a SeedLink client Network GW . Four channels per station: LNZ (1 Hz gravity-referenced vertical envelope — absolute value, no polarity), ENZ (~110 Hz event bursts, gravity-referenced vertical ) and EN1 / EN2 (~110 Hz event bursts, the two horizontals — azimuth not published). Station codes match the station pages (e.g. BH2JN ). In SEED the last letter of a channel code is the component direction, and for all four channels that letter is honest. LNZ is the 1 Hz envelope of gravity-referenced vertical acceleration : each sample is the per-second peak of the absolute value of the vertical component, obtained on the device by projecting every raw sample onto the gravity direction estimated from that same second (the window-mean acceleration, no long-term filter), so a wall-mounted unit and a flat unit give the same definition. The axis is an estimate, not a levelled one: asymmetric shaking inside a window tilts the window mean and the projection axis with it, in proportion to shaking amplitude over g. It is an envelope, not a waveform: non-negative, no polarity, no phase, so the trace never crosses zero; do not rotate it with the horizontals and do not treat it as a signed component. Samples archived before 10 September 2026 were the three-axis vector magnitude instead (see the HISTORY comment in StationXML). ENZ is a signed single component (~110 Hz, gappy — triggers only) and it is gravity-referenced vertical : since 5 August 2026 the burst samples are rotated into a local frame established from gravity before they are published, so StationXML reports Azimuth 0 , Dip -90 (positive up). EN1 and EN2 are the two horizontals, orthogonal to ENZ and to each other, right-handed with up: their Dip is 0 and their Azimuth is deliberately absent — the devices carry no magnetometer, so gravity gives us "down" but not "north". SEED reserves the N / E component letters for true north and east, which is why they carry 1 / 2 instead; if you need geographic horizontals, they are not in this data. All four are uncalibrated — the published response is a nominal datasheet sensitivity (counts = m/s² × 10⁶), not a per-unit calibration. Provisional: the codes are kept to avoid breaking live clients — an earlier version of this page said true three-component data was planned and that these codes would change meaning when it shipped; it shipped on 5 August 2026 and the codes did not change. Anchor your processing to the StationXML <Description> , not the code. Read-only · public · no key. Network GW is a permanent, FDSN-registered code, but the sensors are uncalibrated MEMS: StationXML serves level=channel , where each channel states in its <Description> what the samples actually are, but level=response serves a nominal instrument sensitivity (counts = m/s² × 10⁶, derived from the sensor datasheet). It is not a per-unit calibration and carries no poles/zeros model. There are four channels per station — LNZ , ENZ , EN1 , EN2 — and StationXML publishes Azimuth / Dip only where they are known: ENZ carries Azimuth 0 , Dip -90 because gravity gives us the vertical axis; the two horizontals carry Dip 0 with no Azimuth , because without a magnetometer we know they are orthogonal but not which way they point; LNZ also carries Azimuth 0 , Dip -90 — the measured axis is the vertical, even though the samples are absolute values. An absent field there means unknown, not forgotten — each channel carries a comment saying which case it is. Good to know What the data is — and isn't. Network-confirmed events 3+ GeoShake stations must agree before an event is published — a conservative catalog with a low false-alarm rate. Trigger-window snippets only Waveform snippets are stored around trigger windows only . GeoShake does not archive continuous waveforms. A null inside samples is a missing sample (gap) — it is not a zero reading; do not plot it as 0. Intensity ≠ magnitude Classes hafif · orta · şiddetli are network-derived shaking categories. max_pga is the highest measured peak ground acceleration across triggering stations, taken from the 1 Hz feature stream at the moment the event was solved. It is a three-component vector magnitude (not the max-horizontal convention used by most GMPEs; measured ratio 1.03–1.16×). If a station's measurement had not arrived yet, its trigger-onset amplitude is used instead, so the value is a lower bound. Before 2026-09-20 this field carried the trigger-onset amplitude, which under-reads the true peak by a median factor of 2.94 (measured, n=14); historical rows have been recomputed. This set is not closed — we may add a class later, so treat an unfamiliar intensityClass as a display value rather than an error. A complement, not a replacement A community network — data quality varies with station density. It complements national networks (AFAD/Kandilli, USGS…), it doesn't replace them. Uncalibrated sensors Stations are consumer-grade MEMS accelerometers. They are not calibrated : the response served at level=response is a nominal datasheet sensitivity, not a per-unit calibration — no shake-table calibration, no coupling or mounting correction, no poles/zeros model. Amplitudes are indicative, not metrologically traceable. Elevation is a model, not a survey Station elevation is sampled from a digital elevation model (DEM) at the reported coordinates. It is not a survey , and it describes the terrain rather than the sensor — a unit on an upper floor of a building sits above the published figure. Where elevation is unknown the StationXML schema still requires the field, so 0 is published and the station comment says it means "unknown", not sea level . Depth stays 0 : the sensor's height above the local ground surface is not recorded. Network code is registered The code GW in StationXML, SAC and SeedLink is permanent and registered with the FDSN — since 27 August 2026, as GeoShake Global Seismic Network , DOI 10.7914/ft1b-4x43 ; the FDSN registry entry is public. It will not change, so you can safely rely on it. Holding GeoShake files from before 27 Jul 2026? They carry GS , which was a mistake on our part — the FDSN has GS assigned to a USGS network.
